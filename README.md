# 🎯 SkillFlow — Performance Review System

> **Система мониторинга развития технических навыков сотрудников.**  
> Хакатон-проект: управление профилями, скиллами, планами обучения, встречами 1:1 и проблемами.

---

## 📖 Описание

**SkillFlow** — это платформа для проведения Performance Review и трекинга развития сотрудников. Система позволяет:

- Вести профили сотрудников, загружать аватары и описания.
- Управлять иерархией подразделений и назначать руководителей.
- Вести справочник технических скиллов по направлениям (`BACK`, `FRONT`, `QA`).
- Планировать развитие: годовые планы обучения и привязка скиллов к планам.
- Планировать и проводить встречи (`1:1`, `Skill Review`, `Problem Review`), фиксировать итоги.
- Отслеживать проблемы и риски по сотрудникам.
- Назначать права администратора и управлять пользователями.

## 🏗 Архитектура

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Frontend  │     │    Nginx    │     │   Backend   │
│ React (CRA) │◄───►│   Proxy     │◄───►│ Node/Express│
│ :3000       │     │ :80/:443    │     │ :3001       │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                               │
                 ┌─────────────────────────────┴────────────┐
                 │                                          │
                 ▼                                          ▼
          ┌─────────────┐                            ┌─────────────┐
          │ PostgreSQL  │                            │    Redis    │
          │ (внешняя БД)│                            │    :6379    │
          └─────────────┘                            └─────────────┘
```

- **Клиент** общается с **Nginx** (порт `80`).
- **Nginx** проксирует статические запросы на **фронтенд** (`:3000`), а `/api/*` — на **бэкенд** (`:3001`).
- **Бэкенд** использует **внешнюю БД PostgreSQL** (сервис закомментирован в `docker-compose`, подключается через `DATABASE_URL`) и **Redis** для кэша/очередей.

## 🚀 Быстрый старт

### 📌 Требования
- [Docker](https://www.docker.com/) и [Docker Compose](https://docs.docker.com/compose/)
- Node.js 20+ (для локальной разработки без Docker)

### 🐳 Запуск через Docker (рекомендуется)

1. **Клонируйте репозиторий и перейдите в папку проекта.**

2. **Настройте переменные окружения:**
   ```bash
   cp .env.example .env
   ```
   Откройте `.env` и заполните значения (см. раздел [Переменные окружения](#-переменные-окружения)).

3. **Соберите и запустите контейнеры:**
   ```bash
   docker-compose up -d --build
   ```

4. **Примените миграции БД и сидирование (внутри контейнера бэкенда):**
   ```bash
   docker-compose exec backend npx prisma migrate deploy
   docker-compose exec backend npx prisma db seed
   ```

5. **Откройте приложение:**
   - Фронтенд (через Nginx): `http://localhost`
   - Фронтенд напрямую: `http://localhost:3000`
   - Бэкенд (проверка здоровья): `http://localhost:3001/api/health`

### 💻 Локальная разработка без Docker

#### Backend
```bash
cd backend
npm install
cp .env.example .env   # Заполните DATABASE_URL и JWT_SECRET
npm start              # или `npm run dev` для hot-reload
```

#### Frontend
```bash
cd frontend
npm install
cp .env.example .env   # Заполните REACT_APP_API_URL и моки
npm start              # Запустится на :3000
```

## ⚙️ Переменные окружения

### Корневой `.env` (для `docker-compose`)
| Переменная        | Описание                                      | Пример                  |
|-------------------|-----------------------------------------------|-------------------------|
| `DB_PASSWORD`     | Пароль владельца БД (если используется локальный PostgreSQL) | `REPLACE_WITH_OWNER_PASSWORD` |
| `APP_DB_PASSWORD` | Пароль приложения для БД                      | `REPLACE_WITH_APP_PASSWORD`   |
| `DEMO_PASSWORD`   | Пароль для демо-пользователей                 | `REPLACE_WITH_DEMO_PASSWORD`  |
| `JWT_SECRET`      | Секрет для генерации токенов                  | `REPLACE_WITH_RANDOM_SECRET`  |
| `NODE_ENV`        | Режим окружения                               | `development`               |
| `API_URL`         | URL бэкенда                                   | `http://localhost:3001`     |

### `backend/.env`
| Переменная      | Описание                                      | Пример                  |
|-----------------|-----------------------------------------------|-------------------------|
| `PORT`          | Порт сервера                                  | `3001`                  |
| `DATABASE_URL`  | Строка подключения к PostgreSQL               | `postgresql://user:pass@host:port/db?sslmode=require` |
| `JWT_SECRET`    | Секрет для сессий                             | `super_secret_key`      |

### `frontend/.env`
| Переменная            | Описание                                      | Пример        |
|-----------------------|-----------------------------------------------|---------------|
| `REACT_APP_API_URL`   | Базовый путь к бэкенду (через прокси)         | `/api`        |
| `REACT_APP_USE_MOCK`  | Использовать мок-данные (для демо без бэка)   | `true`/`false`|

> ⚠️ **Важно:** Никогда не коммитьте файлы `.env` в репозиторий. Они уже добавлены в `.gitignore`.

## 🔌 Основные API-эндпоинты

> Полный список роутов находится в `backend/src/routes/` и `backend/src/api/`. Ниже — основные.

### Авторизация
- `POST /api/auth/login` — Вход в систему
- `POST /api/auth/logout` — Выход

### Пользователи
- `GET /api/users` — Список пользователей
- `GET /api/users/:id` — Профиль пользователя
- `GET /api/users/me/profile` — Полный профиль текущего пользователя (скиллы, достижения, руководитель)
- `POST /api/users/me/avatar` — Загрузка аватара
- `PATCH /api/users/me/bio` — Обновление описания "О себе"

### Встречи
- `GET /api/meetings/status` — Статус текущей/следующей встречи
- `GET /api/meetings/upcoming` — Предстоящие встречи
- `GET /api/meetings/history` — История встреч
- `GET /api/meetings/:id` — Детали встречи
- `POST /api/meetings` — Создание встречи

### Скиллы
- `GET /api/skills` — Список скиллов
- `GET /api/skills/:id` — Детали скилла
- `POST /api/skills` — Создание скилла
- `PUT /api/skills/:id` — Обновление скилла
- `DELETE /api/skills/:id` — Архивация скилла

## 🐳 Особенности конфигурации

- **Внешняя БД:** В `docker-compose` сервис `postgres` закомментирован. Проект использует внешнюю БД (например, на Railway), заданную через `DATABASE_URL`. Для локального запуска раскомментируйте сервис `postgres` и укажите свои креды.
- **Моки на фронтенде:** При `REACT_APP_USE_MOCK=true` фронтенд работает с демо-данными из `src/shared/mocks/` и `src/data/`. Для интеграции с реальным бэкендом установите `false`.
- **CRA vs Vite:** Основной запуск фронтенда — через `react-scripts` (порт `3000`). Файлы `vite.config.js` и корневой `index.html` присутствуют как альтернатива, но не используются в текущих скриптах `package.json`.
